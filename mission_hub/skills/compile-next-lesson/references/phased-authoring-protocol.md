# Phased fresh-context authoring protocol

Do not ask one Luna context to interpret the mission, design the story, construct every exercise,
plan visuals, and assemble the runtime. The monolithic L000 trial repeated semantic defects at
medium, high, and xhigh while appearing structurally complete. Use fresh contexts and immutable
stage outputs.

Every stage receives `lesson-builder-mission.json` first, then one bounded task card, the frozen
selection/evidence packet, and only the accepted upstream artifacts it consumes. Bind the full
source paths and hashes in the orchestration manifest, but do not flood the active prompt with the
entire wiki or unrelated policies. A stage may query a relevant source when uncertain. It must
record which source resolved the question.

Every model-authored stage must pass its deterministic stage validator before semantic review.
The model's statement that it validated its own output is not evidence. A hash mismatch, illegal
field, or wrong chronology mode is a contract failure and stops the effort ladder until repaired.

## Stage 0 — deterministic selection

Deterministic code selects the exact next conducted entry and binds learner state, known closure,
curriculum, and rehearsal hashes. No model may change the entry, Point, prerequisites, or cursor.

## Stage 1 — material selection

Fresh Luna context. Read the selected entry, learner state, known closure, and mission card. Freeze
the lesson thesis and choose the tested vocabulary/material. Record what Ninereeds can bankably do,
the exact language and world outcomes, material-count judgment, structural exceptions, forbidden
assumptions, and identity/chronology hazards. L000 records zero vocabulary items because its tested
material is a staged set of communicative operations. Do not write presentation or practice.

Partition lexical material into ordered four-item sets. The ordinary authoring loop completes one
set before opening the next:

1. freeze the four items and their exact meanings;
2. write four affirmative items;
3. write four negative items;
4. write four W-question items;
5. write four OR-question items;
6. write any Point-specific response family;
7. validate the closed set, then repeat for the next four items.

Do not produce all affirmative questions for the whole lesson and then recover the item groupings
later. The four-item micro-batch is the bounded context and review unit. L000 is a structural
nonlexical exception: apply the same loop to its frozen participant/operation exemplars rather than
inventing vocabulary slots.

## Stage 2 — local presentations

Fresh Luna context. Produce the modeled lead-in for each tested gate and bind it to that gate.
Presentation is not one front-loaded lesson phase. The executable lesson always emits a gate's
accepted model immediately before that gate's controlled prompts. Preserve every model as ordered,
speaker-attributed turn objects, never as a flattened dialogue string. Every turn binds one full
relational scene and, when needed, only the current speaker's accepted portrait/representation.
Do not write exercises. L000 binds greeting and participant self-identification to the affirmative
bootstrap, then uses one local model each for affirmative, negative, W-question, OR-question, and
reciprocity.

## Stage 3 — affirmative controlled practice for one set

Fresh Luna context receives exactly one accepted four-item set. Produce its four affirmative
prompts/answers, visual truth requirements, scoring contract, and pre-authored reserves. Isolate
the affirmative response operation. At runtime, emit its bound local presentation immediately
before these prompts.

## Stage 4 — negative controlled practice for the same set

Fresh Luna context. Produce the closed negative pool and reserves. Isolate the negative response;
do not append an affirmative correction or another response operation.

## Stage 5 — W-question controlled practice for the same set

Fresh Luna context. Produce the closed W-question pool and reserves using only accepted presentation
forms and learner-self identity rules.

## Stage 6 — OR-question controlled practice for the same set

Fresh Luna context. Produce the closed OR-question pool and reserves. Make every alternative and
correct response explicit; do not rely on implicit speaker perspective.

## Stage 6A — Point-specific additional gate

Use only when the selected Point contains an operation not covered by the four default gates. It is
its own fresh Luna context with presentation, controlled items, reserves, and scoring. L000 uses this
stage for meeting reciprocity. Do not hide an additional Point operation inside openings, feedback,
or recap.

## Stage 7 — mixed practice

Repeat Stages 3–6 (and 6A when applicable) for every accepted four-item set before Stage 7 begins.
Then a fresh Luna context consumes only the accepted set/family artifacts. Freeze a varied order
containing all base items, acquisition bounds, semantic/language score separation, and the frozen
TRAIN_LONGER ordering. It may recombine accepted gates but may not create a new form or item live.

## Stage 8 — picture-book script

Fresh Luna context. Construct one coherent grounding micro-event with initial state or goal,
meaningful development, and resolution/stopping state. Realize it as pages with persistent scene
facts and closed, speaker-attributed dialogue turns. Every question has an explicit response. The
story need not contain every practice form and may not change the Point or world objective.

## Stage 9 — presentation and practice visuals

Fresh Luna visual-planning context, followed by production and independent pixel acceptance.
Commission or reuse the exact visuals required by Stages 2–7. Build the visual brief only after the
dialogues are frozen. It combines the complete vocabulary inventory with a dialogue truth table:
exact speaker, referent, positive/negative match, W target, OR alternatives, distractors, spatial or
social relations, and context required to verify the answer. Never prompt from a bare vocabulary
list when the dialogue asserts a relation. Every exercise must map to a visual satisfying its own
truth row; an available generic scene cannot be substituted merely because it contains some of the
same entities. A crop or highlight is optional and must solve a named pointing/salience problem.
Relational claims preserve every operand and enough context to judge the relation. Preserve prompts,
attempts, hashes, review receipts, and rejections.

## Stage 10 — picture-book captions

Fresh Luna context. Derive learner-visible captions from the accepted story turns using only the
frontier and known closure. Do not replace dialogue with descriptive operator prose. Keep scene
descriptions separate as operator-only facts.

## Stage 11 — picture-book visuals

Fresh Luna visual-planning context, followed by production and pixel review. Bind each page and
speaker turn to exact full scenes and any justified speaker cue. Reuse is allowed only when the
resulting displayed page still makes the story state and turn attribution observable. Crops remain
optional. Do not let a parent master's truth excuse an incomplete displayed derivative.

## Stage 12 — picture-book comprehension

Fresh Luna context. Read the accepted story script, captions, and exact accepted pixels. Produce
only checks that require attention to this event. Every nonverbal selection freezes its machine
action, null spoken instruction, inspectable option objects, option assets, expected option IDs,
and cited story-turn evidence. Separate direct application from narrative comprehension.

## Stage 13 — exact script assembly

Fresh Luna context. Perform a lossless assembly of accepted artifacts. It may not rewrite dialogue,
drop turns or options, flatten speakers, improvise assets, or omit intervention pools. Bind exact
order, answer contracts, reserves, TRAIN_MORE/TRAIN_LONGER budgets and stop rules, alarms, report
fields, and provenance. Any mismatch returns to the owning stage.

## Stage 13A — static independent review gate

Fresh Sol context. Review the assembled lesson anonymously against learner state, curriculum Point,
mission card, relevant wiki, upstream artifacts, and exact pixels. Grade semantic mission fit,
story coherence, identity safety, language closure, dual-use grounding, completeness, visuals,
interventions, and alarms. Visual review includes necessity and relation-operand completeness. Sol
returns `revise` with an owning-stage repair request or `pass`; it never rewrites the lesson.

## Stage 14 — inspection PDF

Generate the PDF deterministically from the script that passed static review. It contains the exact
images shown, captions, speaker-attributed turns, prompts, answer contracts, story, comprehension,
intervention controls, and provenance needed for operator inspection. The PDF is a projection, not
a second lesson authority.

## Rehearsal and release gates

Static-review pass unlocks rehearsal; PDF generation alone does not. A fresh teacher context and a
separate learner-simulator context conduct the lesson from the frozen script and log every event.
A fresh anonymous reviewer then grades the log, teacher report, learner behavior, interventions,
and alarms. Repairs return to the owning authoring stage and repeat static review, PDF generation,
and rehearsal as required. The final repaired PDF is presented for operator approval. Only operator
approval permits advancing to the next curriculum lesson; actual-student teaching remains locked.

## Retry and context rules

- Start each Luna stage at medium effort.
- Escalate medium → high → xhigh → max only for a model-attributable failure on unchanged inputs.
- Missing prerequisites, unclear contracts, unavailable assets, or contradictory upstream artifacts
  stop the effort ladder and repair the owning stage or policy.
- Never overwrite an attempt. Link its input hashes, output hash, verdict, and next disposition.
- Downstream stages consume accepted artifacts only; they do not receive failed drafts unless the
  task is explicitly failure analysis.
- A fresh context does not inherit informal conversation. Its mission card and bounded artifact are
  the complete operational handoff.
